Расширение `ТестовоеЗаданиеПользователь` ставится клиенту вместо полного `ТестовоеЗадание`. Вместе их не подключают. Полное расширение в этом этапе не менялось.

База: `F:\1с\TestCoder\БазаПользователь`, в списке баз «TestCoder Пользователь». Восстановлена из `D:\cursor\TestCoder\backup\baza_do_etapa1.dt`. Рабочая база `F:\1с\TestCoder\База` не открывалась. В бэкапе было пустое расширение «ТестовоеЗадание» (язык и роль «тз Основная роль», без объектов механизма). Оно удалено командой `/DeleteCfg -Extension ТестовоеЗадание` только в базе пользователя.

`load_user.cmd`: загрузка 0, обновление 0, проверка модулей 0, в журнале «Синтаксических ошибок не обнаружено!». `dump_user.cmd`: 0. Выгрузка скопирована в `TestZadanie_user` вместе с `ConfigDumpInfo.xml`. Предприятие не запускалось.

## Что перенесено

Наценка: макет `тз_ВнешняяОбработкаНаценки` (тот же `Template.bin`), расчёт, константы процента и ссылки на скидку, регистр `тз_КратностьПродажи`.

Контроль проведения заказа, реализации, чека ККМ и отчёта о розничных продажах: сумма наценки, запрет ручной скидки, цена не ниже вида цен. Цепочка вида цен: строка, затем соглашение, затем вид цен из `тз_СоглашенияУровней`, если у партнёра есть запись уровня. Для чека сумма сверяется только при `СкидкиРассчитаны = Истина`. Роль обхода `тз_ИзменениеНаценкиЗаНекратность` и `&После("ПриПодготовкеДополнительныхРолейАдминистратора")`.

Уровни: регистры партнёров, ИНН и соглашений уровней, команда «тз Уровень покупателя», загрузка ИНН из CSV, применение по ИНН при записи контрагента, бронзовый уровень новому клиенту, `&Вместо` `ПолучитьУсловияПродажПоУмолчанию`. Сегмент партнёра берётся из реквизита `СегментПартнеров` соглашения, записанного в регистре уровня. Сегмент по наименованию не создаётся.

Команда «тз Наценка поверх скидок (перестроить группы)» с вопросом перед выполнением.

Роли: «тз Основная» (роль по умолчанию), «тз Настройка наценки и уровней», «тз Изменение наценки за некратность», заимствованные полные права.

Команда «тз Первоначальная настройка» — только полноправный пользователь. Идемпотентно: включает `ИспользоватьАвтоматическиеСкидкиВПродажах`, ставит процент 20, если константа пустая, регистрирует внешнюю обработку из макета, создаёт скидку «Наценка за некратность упаковке» и действие на пустой склад. Если в `тз_СоглашенияУровней` нет соглашений, протокол просит заполнить регистр.

Регистры кратности, ИНН и соглашений уровней стоят в подсистеме «тз Наценки и уровни» со стандартными формами списка. Изменение — у роли настройки и полных прав.

## Что убрано

Команда «тз Заполнить уровни и цены» и весь код создания тестовых данных: единица «рулон», упаковки, виды номенклатуры, номенклатура, виды цен, установка цен, сегменты по наименованию, соглашения, партнёры, контрагенты, записи ИНН, розничная цена РМК. Команда «тз Настроить наценку за некратность» заменена первоначальной настройкой без НСИ.

Константа `тз_ОтладкаКонтроля` и журнал решений контроля. Остаётся предупреждение журнала регистрации о уже пробитом чеке.

Пустые заимствования видов номенклатуры, номенклатуры, скидок и дополнительных обработок не переносились: код обращается к объектам основной конфигурации.

Контроль «соглашение документа совпадает с уровнем партнёра» не делается. Возможное развитие: при проведении заказа и реализации сравнивать соглашение шапки с соглашением из `тз_СоглашенияУровней` и отказывать, если у партнёра есть уровень, а соглашение другое и не индивидуальное.

## Права менеджера по продажам

Профиль «Менеджер по продажам» описан в `УправлениеДоступомУТ`, область `Описание_профиля_МенеджерПоПродажам` (строка 933). В него входят чтение цен (`ЧтениеЦенНоменклатуры`) и изменение индивидуальных соглашений (`ДобавлениеИзменениеИндивидуальныхСоглашенийСКлиентами`). Значение доступа `СоглашенияСКлиентамиИзменение` для профиля — только «Индивидуальные» (строка 1170). Роль изменения ограничивает добавление и изменение соглашений этим видом доступа.

Изменение справочника `СкидкиНаценки`, регистра `ДействиеСкидокНаценок` и справочника `ВидыЦен` есть у роли `ДобавлениеИзменениеПравилЦенообразования`. Изменение документа `УстановкаЦенНоменклатуры` — у роли `ДобавлениеИзменениеЦенНоменклатуры`. Типовые соглашения — у роли `ДобавлениеИзменениеТиповыхСоглашенийСКлиентами`. Эти три роли входят в профиль «Маркетолог» (`УправлениеДоступомУТ`, строки 504–505 и 562), не в профиль менеджера по продажам.

Менеджер по продажам штатно не меняет нашу скидку, её действие, вид цен, документ установки цен и типовое соглашение уровня. Он может вести индивидуальное соглашение своего клиента. Скидку, прайс и типовые соглашения меняет пользователь с профилем маркетолога или с полными правами. Руководитель отдела продаж получает роль типовых соглашений (`ДобавлениеИзменениеТиповыхСоглашенийСКлиентами`, строка 757) и по комментарию профиля делает все соглашения; ролей скидок и установки цен в этом профиле нет.

## Обработка тестовых данных

`epf_user_data` собирается `scripts\build_user_data_epf.cmd` в `dist\тз_ЗаполнениеТестовыхДанных.epf` (файл epf в git не входит). Обработка для тестировщика: одной кнопкой выполняет первоначальную настройку расширения и шаги стенда (виды номенклатуры, кратность, три ручных вида цен, цены, сегменты, типовые соглашения, регистр уровней, ИНН золотого клиента, два клиента). Уровень партнёра пишут обработчики расширения, не менеджер записи регистра. У клиента те же данные заводят вручную по `TestZadanie_user\README.md`: у обработки фиксированные демонстрационные наименования и цены.

## Безопасный режим

При первой загрузке расширения в базу платформа включает «Безопасный режим». В журнале сеанса это строка: расширение модуля `ОбщийМодуль.УправлениеДоступомСлужебный` запрещено, потому что расширение подключено в безопасном режиме. Пока флажок стоит, не подключается `&После("ПриПодготовкеДополнительныхРолейАдминистратора")`, и роль обхода не добавляется администраторам. Код не может включить привилегированный режим: не записывается состав сегмента уровня и не регистрируется обработка наценки из макета. У «Клиент Золото (тест)» из-за этого оставался бронзовый уровень.

Свойство «Привилегированный» у модуля `УправлениеДоступомСлужебный` в основной конфигурации выключено. Платформа всё равно запрещает расширять этот модуль у расширения в безопасном режиме — так звучит ошибка сеанса.

Ключа DESIGNER нет. В `mngui.dll` у `/LoadConfigFromFiles` есть `-Extension` и нет `SafeMode`. Строка `safe-mode` есть в `configshell.dll` — это команда `ibcmd infobase config extension update --safe-mode=no`. Файла `ibcmd.exe` в поставке 8.5.1.1343 нет. `load_user.cmd` после загрузки печатает, где снять флажок. `load.cmd` не менялся: ключ добавить некуда. Повторная загрузка XML флажок не включает, это свойство расширения в информационной базе.

Снять флажок: конфигуратор, Конфигурация → Расширения конфигурации; либо предприятие, НСИ и администрирование → Печатные формы, отчеты и обработки → Расширения. После снятия сеанс открывают заново.

Полное расширение `ТестовоеЗадание` в рабочей базе `F:\1с\TestCoder\База`. Чтение свойства `БезопасныйРежим` через `РасширенияКонфигурации` не получено: предприятие открыло диалог «Предупреждение безопасности» на отдельную обработку чтения, «Разрешить открывать данный файл?». Нажато «Нет», сеанс закрыт, данные базы не менялись. В журнале регистрации рабочей базы строки «безопасном режиме» нет. Команды полного расширения в этой базе уже регистрировали обработку наценки, писали сегменты и проводили документы с контролем, значит флажок безопасного режима у `ТестовоеЗадание` снят.
