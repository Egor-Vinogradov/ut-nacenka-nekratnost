# тз Тестовое задание (для пользователя)

Расширение `ТестовоеЗаданиеПользователь` ставится вместо полного «ТестовоеЗадание». Оба сразу не подключают. Номенклатуру, виды цен, цены, соглашения и клиентов расширение не создаёт.

У клиента данные заводят вручную по разделу «Настройка у клиента». Обработка `тз_ЗаполнениеТестовыхДанных` для клиента не предназначена: она подставляет фиксированные демонстрационные наименования и цены.

## Быстрый стенд для тестирования

Файл → Открыть → `D:\cursor\TestCoder\dist\тз_ЗаполнениеТестовыхДанных.epf` → «Заполнить». Флажок «Выполнить первоначальную настройку расширения, если не выполнена» по умолчанию включён. Повторное заполнение пишет «без изменений», если стенд уже собран. Перед этим снимите безопасный режим расширения, иначе регистрация обработки наценки и уровень по ИНН не выполнятся. Исходники: `epf_user_data`, сборка: `scripts\build_user_data_epf.cmd`.

## Настройка у клиента

1. Подключить расширение и обновить базу. Войти полноправным пользователем.
2. Снять безопасный режим и заново открыть Предприятие. При первой загрузке в базу платформа включает этот флажок сама. Пока он стоит, сеанс пишет «расширение модуля запрещено», потому что расширение подключено в безопасном режиме. В таком сеансе нельзя включить привилегированный режим: не записывается состав сегмента уровня и не регистрируется внешняя обработка наценки. Не подключается и расширение модуля `УправлениеДоступомСлужебный`, через которое роль обхода добавляется администраторам. В конфигураторе: Конфигурация → Расширения конфигурации → `ТестовоеЗаданиеПользователь` → снять «Безопасный режим». В предприятии: НСИ и администрирование → Печатные формы, отчеты и обработки → Расширения → снять «Безопасный режим». Ключа пакетной загрузки DESIGNER для этого флажка нет.
3. Администрирование → «тз Наценки и уровни» → «тз Первоначальная настройка». Команда включает автоматические скидки в продажах, ставит процент 20, если он ещё пустой, регистрирует внешнюю обработку из макета и создаёт скидку «Наценка за некратность упаковке» с действием на пустой склад. Повторный запуск второй скидки не создаёт. Если регистр соглашений уровней пуст, протокол об этом напишет.
4. Открыть стандартный список «тз Кратность продажи». Для вида номенклатуры, который продаётся упаковками, указать кратность. Наценка считается, когда сумма количества по номенклатуре и характеристике этой кратности не кратна.
5. Своими средствами создать три вида цен и три типовых соглашения с сегментами клиентов. Вид цен соглашения — тот, по которому контролируется цена уровня.
6. В списке «тз Соглашения уровней» на каждый уровень (бронзовый, серебряный, золотой) записать своё типовое соглашение и вид цен. Сегмент партнёра расширение берёт из соглашения этой записи, отдельный сегмент по имени не создаёт.
7. По необходимости, тем же полноправным пользователем: «тз Наценка поверх скидок (перестроить группы)». Команда спрашивает подтверждение, собирает прочие скидки корня в группу «Маркетинговые скидки (тз)» и ставит корню сложение.
8. Список «тз Уровни покупателей по ИНН» заполнить вручную или командой «тз Загрузить уровни по ИНН» из CSV: ИНН, точка с запятой, уровень (бронзовый, серебряный, золотой или 1, 2, 3). При записи контрагента уровень переносится партнёру, если уровень не задан вручную. Новый клиент без ИНН получает бронзовый.
9. Роли. «тз Основная» стоит по умолчанию: проведение и чтение регистров. «тз Настройка наценки и уровней» даёт изменение трёх регистров и команды уровня и загрузки ИНН. «тз Изменение наценки за некратность» пропускает контроль наценки и цены. Первоначальная настройка и перестройка групп в коде доступны только полноправному пользователю.

Процент наценки потом меняется константой «тз Процент наценки за некратность». Кратность по видам номенклатуры ведётся в регистре, не в константе.
