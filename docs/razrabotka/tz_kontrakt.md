# Контракт этапа 1

Источник — выгрузка `osn` (УТ 11.5.27.101). Сигнатуры не дополнялись: если метода нет, это написано явно.

## 1. Внешняя обработка вида «РасчетСкидкиНаценки»

### СведенияОВнешнейОбработке

Шаблон структуры собирает `ДополнительныеОтчетыИОбработки.СведенияОВнешнейОбработке(ВерсияБСП = "") Экспорт`.

`ДополнительныеОтчетыИОбработки.СведенияОВнешнейОбработке`, `osn\CommonModules\ДополнительныеОтчетыИОбработки\Ext\Module.bsl`, строки 310–341: экспортная функция с необязательным аргументом версии БСП, возвращает структуру-шаблон.

Ключи структуры:

| Ключ | Значение в шаблоне |
|---|---|
| Вид | `""` |
| Версия | `"0.0"` |
| Назначение | пустой массив |
| Наименование | `Неопределено` |
| БезопасныйРежим | `Истина` |
| Информация | `Неопределено` |
| ВерсияБСП | аргумент функции |
| ОпределитьНастройкиФормы | `Ложь` |
| НазначениеВариантаОтчета | только если есть подсистема «ВариантыОтчетов» |
| Команды | таблица: Представление, Идентификатор, Использование (Строка), ПоказыватьОповещение, Модификатор, Скрыть, ЗаменяемыеКоманды — типы колонок взяты из реквизитов ТЧ `Команды` справочника |
| Разрешения | пустой массив |

Внешний объект обязан экспортировать свою `СведенияОВнешнейОбработке()`. Её вызывает `ПриПолученииРегистрационныхДанных` (строка 3204) и результат накладывается на шаблон через `ОбщегоНазначенияКлиентСервер.ДополнитьСтруктуру(..., Истина)` — одноимённые ключи заменяются (строка 3205; процедура дополнения — `osn\CommonModules\ОбщегоНазначенияКлиентСервер\Ext\Module.bsl`, строка 643).

Для этого вида типовой помощник задаёт вид перечислением, а не строкой:

`СкидкиНаценкиСервер.ПараметрыРегистрацииВнешнейОбработкиСкидкиНаценки`, `osn\CommonModules\СкидкиНаценкиСервер\Ext\Module.bsl`, строки 82–96: экспортная функция кладёт в параметры регистрации вид `РасчетСкидкиНаценки`, версию 1.0, безопасный режим истина, версию БСП 2.1.2.1 и пустую таблицу команд.

`ДополнительныеОтчетыИОбработки.ПолучитьВидОбработкиПоСтроковомуПредставлениюВида` (строка 2010) знает только виды БСП (заполнение, отчёт, печатная форма, создание связанных, шаблон сообщения, дополнительная обработка, дополнительный отчёт). Строки `РасчетСкидкиНаценки` в этой функции нет: для неё функция ничего не возвращает. Поэтому в `СведенияОВнешнейОбработке` внешней обработки `Вид` должен быть ссылкой `ПеречислениеСсылка.ВидыДополнительныхОтчетовИОбработок.РасчетСкидкиНаценки`, как в помощнике выше. Иначе `ЗарегистрироватьОбработку` запишет в реквизит `Вид` строку или `Неопределено`.

Команды для вида «расчёт скидки» помощник не заполняет: пустая таблица.

### Вызов Рассчитать

`СкидкиНаценкиСервер.РассчитатьСкидку`, строки 3875–4038. Перед вызовом (строка 3877) товары берутся из `СтрокиТоваровДляРаспределения`, а пустой результат — из `ПустаяТаблицаСкидокСРасшифровкой`.

Вызов внешней обработки, строки 4024–4038: если способ предоставления — ссылка на дополнительный отчёт или обработку, объект берётся через `СкидкиНаценкиПовтИсп.ОбъектВнешнейОбработки`. На время вызова включается безопасный режим. `Рассчитать` получает строку дерева скидок, значение из хранилища параметров этой строки, таблицу товаров и структуру параметров расчёта. После вызова безопасный режим выключается. Строка дерева помечается рассчитанной, в неё кладётся результат.

Четыре аргумента:

1. `СтрокаДерева` — строка дерева скидок (`СформироватьДеревоСкидок`), не ссылка справочника. Дальше по коду у этой строки читаются `Ссылка`, `ЗначениеСкидкиНаценки`, `СпособПредоставления`, `ПараметрыВнешнейОбработки`, `ПараметрыУсловий`, `Управляемая`, `НазначенаПользователем`, `СпособПримененияСкидки`.
2. `СтрокаДерева.ПараметрыВнешнейОбработки.Получить()` — произвольное значение из хранилища значения элемента скидки. Отдельной структуры в этом вызове нет.
3. `Товары` — см. п. 2.
4. `ПараметрыРасчета` — структура `ПараметрыРасчета()` (строка 7716): `СкидкиНаценки`, `Партнер`, `Соглашение`, `Регистратор`, `БазоваяВалюта`, `ФормаОплаты`, `ДеньНедели`, `ТекущееВремя`, `ТекущаяДата`, `ГрафикОплаты`, `КартаЛояльности`, `Товары`, `ВалютаДокумента`, `ВалютаУправленческогоУчета`, `Пользователь`, `Объект`. К моменту вызова в неё уже положены таблица товаров и пустые таблицы результата.

### Что обязано вернуться

Функция должна вернуть таблицу значений того же состава, что `ПустаяТаблицаСкидокСРасшифровкой`.

`ПустаяТаблицаСкидокСРасшифровкой`, строки 7509–7520: экспортная функция. Без параметров расчёта собирает таблицу с колонками `КлючСвязи` (число), `Расшифровка` (таблица значений), `Сумма` (число), `Действует` (булево). Если параметры переданы, копирует колонки уже заготовленной таблицы из этих параметров.

`ПустаяТаблицаРасшифровка`, строки 7532–7542 (между функциями — `КонецФункции` и комментарий, строки 7522–7531): колонки `СкидкаНаценка` (ссылка на скидку), `Сумма` (число), `ЭтоСообщение` (булево). С переданными параметрами — копия колонок заготовки.

Состав внешней таблицы:

| Колонка | Тип |
|---|---|
| КлючСвязи | Число |
| Расшифровка | ТаблицаЗначений |
| Сумма | Число |
| Действует | Булево |

`Расшифровка` — таблица `ПустаяТаблицаРасшифровка` (строки 7532–7538):

| Колонка | Тип |
|---|---|
| СкидкаНаценка | СправочникСсылка.СкидкиНаценки |
| Сумма | Число |
| ЭтоСообщение | Булево |

Образец заполнения одной строки — `ПрименитьЗначениеСкидкиКТовару` (строка 3809) и `ПолучитьРасшифровкуСкидки` (строка 3762): `КлючСвязи` строки товара, `Действует = Истина`, в расшифровке `СкидкаНаценка = СтрокаДерева.Ссылка`, `Сумма` — сумма этой скидки по строке, `ЭтоСообщение = Ложь`.

Знак суммы. Для процентной скидки движок считает `ЗначениеСкидкиНаценки / 100 * остаток` (строка 3887) и вычитает эту сумму из суммы строки (`ПрименитьРезультатРасчетаКОбъекту`). Положительная сумма уменьшает сумму строки. Наценка — отрицательная сумма в возвращаемой таблице. Значение элемента скидки само по себе в ветке внешней обработки не подставляется: сумму считает `Рассчитать`.

Строки с `Действует = Ложь` в документ не попадают: группа-родитель копирует из подчинённого результата только строки с `Действует` (`ЗаполнитьТаблицуДанныхПодчиненныхСтрок`, строки 1258–1262). То же отсечение — в `ПолучитьИтогРезультатаРасчета` (строка 3382).

### Как результат попадает в документ

1. `РассчитатьСкидку` кладёт возврат в `СтрокаДерева.РезультатРасчета` (строки 4037–4038).
2. `РассчитатьДеревоСкидок` разворачивает расшифровку. В плоскую таблицу попадает `КлючСвязи` внешней строки и поля `Расшифровка`: `СкидкаНаценка`, `Сумма`, `ЭтоСообщение`. Колонка `Сумма` самой строки результата в этом цикле не читается — в документ уходит `Расшифровка.Сумма`. Строки 4094–4110: создаётся таблица из этих четырёх колонок, в неё копируются строки каждой расшифровки, затем таблица сворачивается по ключу связи, скидке и признаку сообщения с суммированием суммы.

Дальше к плоской таблице добавляются `НапомнитьПозже` и `СпособПримененияСкидки` из дерева (строки 4113–4119).

3. `ПрименитьРезультатРасчетаКОбъекту` загружает эту плоскую таблицу в ТЧ `СкидкиНаценки`. Строки 4290–4296: если это реализация сверх заказа, строки добавляются по одной с заполнением свойств; иначе табличная часть загружается целиком.

Сумма по строке товара считается так: автоматические скидки сворачиваются по `КлючСвязи` (строка 4301), сумма строки уменьшается на эту величину (строки 4347–4349). Процент автоматической скидки — стократное отношение суммы скидки к сумме без скидки, ноль если базы нет. Сумма строки — база минус скидка, но скидка не больше базы. Положительная сумма в возврате — скидка, отрицательная увеличивает сумму строки.

## 2. Какие товары приходят в Рассчитать

Не всегда весь документ.

`СтрокиТоваровДляРаспределения` (строки 3631–3643):

- если `СтрокаДерева.ПараметрыУсловий.ЕстьУсловияПоСтроке` — массив строк из `ПараметрыРасчета.Товары`, отобранных по `КлючСвязи` из `ТаблицаПроверкиУсловий`;
- иначе — сама таблица `ПараметрыРасчета.Товары`.

`ЕстьУсловияПоСтроке` становится истиной, когда «условием» выступает сама скидка, то есть у неё отбор номенклатуры не «без ограничений» или задан дополнительный отбор. Это добавляет `ЗапросТЧУсловияПредоставления` (строки 4522–4532). Условие из справочника `УсловияПредоставленияСкидокНаценок` считается ограничением документа целиком (`ПроверитьУсловия`, строки 6266–6267) и в результат проверки пишется с `КлючСвязи = -1` (`ОбъединитьРезультаты`, строки 6199–6202).

Таблица товаров собирается запросом документа. Для заказа — `РассчитатьПоЗаказуКлиента`, строки 1878–1910; общая выборка полей — `ДанныеПоТоварамИНаборам`, строки 6660–6673. В строке есть:

`КлючСвязи`, `Номенклатура`, `Характеристика`, `Упаковка`, `Серия`, `Склад`, `ВидЦены`, `ЦеноваяГруппа`, `Количество`, `КоличествоУпаковок`, `Цена`, `Сумма` (`Сумма = Цена * КоличествоУпаковок`).

При включённых наборах добавляются поля набора. Многооборотная тара в запрос не попадает, если `ВернутьМногооборотнуюТару` (строки 1918–1923). Строки набора с ценой за набор в эту таблицу не входят (отбор строк 6677–6679).

Итог для нашей наценки: при отборе номенклатуры скидки в `Рассчитать` придут только отобранные строки (массив). Без отбора — вся таблица товаров документа. `Количество`, `Характеристика`, `Цена`, `КоличествоУпаковок`, `КлючСвязи` в обеих ветках есть.

## 3. Безопасный режим

Два независимых включения.

1. Место вызова расчёта. `УстановитьБезопасныйРежим(Истина)` непосредственно вокруг `Рассчитать`, затем `УстановитьБезопасныйРежим(Ложь)` (`СкидкиНаценкиСервер`, строки 4027 и 4033). Это булево, не имя профиля. `ВыполнитьВБезопасномРежиме` в этом месте не используется.
2. Подключение объекта. `ДополнительныеОтчетыИОбработки.ПодключитьВнешнююОбработку` читает реквизиты `БезопасныйРежим` и `ХранилищеОбработки` (строка 58). Если включены профили безопасности — режим берётся из `РаботаВБезопасномРежимеСлужебный.РежимПодключенияВнешнегоМодуля` (строки 69–77). Иначе: `БезопасныйРежим = модель сервиса ИЛИ реквизит элемента` (строка 81).

Признак `БезопасныйРежим` у элемента справочника нужен. `ЗарегистрироватьОбработку` копирует его из регистрационных данных (строка 3018). Если в сведениях он `Ложь` и пользователь не полноправный, регистрация отвергается (строки 2993–2995). Помощник скидок ставит `Истина` (строка 90).

Запросы к базе из обработки в безопасном режиме платформа выполняет. Привилегированный режим на время безопасного режима не действует: расчёт документа включает его раньше (`РассчитатьПоЗаказуКлиента`, строка 1870), а вызов обработки тут же включает безопасный режим. Файлы, COM и внешние компоненты в этом вызове недоступны.

## 4. Регистрация из двоичных данных

Экспортная функция, которая заполняет элемент:

`ДополнительныеОтчетыИОбработки.ЗарегистрироватьОбработку(Знач Объект, Знач ПараметрыРегистрации) Экспорт` — строка 2931. Комментарий модуля: «Для внутреннего использования». Функция не записывает элемент и не кладёт двоичные данные в `ХранилищеОбработки`.

Пакетная процедура, которая это делает, не экспортная: `ЗарегистрироватьОтчетыИОбработки` (строка 2758). Другого экспортного метода «зарегистрировать из двоичных данных» в модуле нет. Обработка заполнения должна повторить её шаги и вызвать экспортную `ЗарегистрироватьОбработку`.

Обязательные ключи `ПараметрыРегистрации`, которые процедура реально читает:

- `АдресДанныхОбработки` — адрес временного хранилища с двоичными данными (строка 3193 и 3197);
- `ЭтоОтчет` — для обработки `Ложь` (строка 3006);
- `ИмяФайла` (строка 3020);
- `ОтключатьКонфликтующие` (строка 2939), при истине ещё `Конфликтующие`;
- `ОтключатьПубликацию` (строка 2958).

Что заполняет `ЗарегистрироватьОбработку` из сведений внешней обработки: `Наименование`, `Версия`, `БезопасныйРежим`, `Информация`, `ИмяФайла`, `ИмяОбъекта`, `Вид`, `РежимСовместимостиРазрешений` (`Версия_2_1_3`, а при `ВерсияБСП` старше `2.2.2.0` — `Версия_2_2_2`, строки 3013–3017), табличную часть `Команды`, при необходимости `Назначение`.

Публикацию «Используется» ставит не она, а пакетная процедура до вызова (строка 2814): реквизит `Публикация` становится значением перечисления «используется».

Хранилище и запись — после успешного результата (строки 2853–2854 и 2909): двоичные данные кладутся в `ХранилищеОбработки` со сжатием, имя объекта берётся из метаданных внешнего объекта, элемент записывается через `ОбновлениеИнформационнойБазы.ЗаписатьОбъект` с привилегированным режимом.

Для нового элемента пакетная процедура дополнительно ставит `ИспользоватьДляФормыОбъекта = Истина`, `ИспользоватьДляФормыСписка = Истина`, `Ответственный = Пользователи.ТекущийПользователь()` (строки 2772–2774).

## 5. Регистр цен и функция цены

Два регистра, оба периодичность `Second`, режим записи `RecorderSubordinate`.

`РегистрСведений.ЦеныНоменклатуры` (`osn\InformationRegisters\ЦеныНоменклатуры.xml`, строки 159–160). Измерения: `Номенклатура`, `Характеристика`, `ВидЦены` (строки 399, 447, 495). Ресурс `Цена` (строка 179); рядом ресурсы `Упаковка`, `Валюта`.

`РегистрСведений.ЦеныНоменклатуры25` (`osn\InformationRegisters\ЦеныНоменклатуры25.xml`, строки 159–160). Измерения: `Номенклатура`, `ХарактеристикаЦО`, `СерияЦО`, `УпаковкаЦО`, `ВидЦены` (строки 438, 486, 534, 582, 636). Ресурс `Цена` (строка 179).

Функция получения цены:

`ЦеныПредприятияЗаполнениеСервер.ПолучитьЦенуПоОтбору(ПараметрыОтбора) Экспорт` — строка 492. Возвращает `Число`: `0`, если срез пуст, иначе `Окр(Выборка.Цена, 2)` (строки 625–630).

Параметры — структура `НовыйПараметрыОтбораПолучитьЦенуПоОтбору() Экспорт` (строка 899): `Дата`, `Валюта`, `Номенклатура`, `Характеристика`, `Упаковка`, `Серия`, `ВидЦены`.

Какой регистр читать, решает `ЦенообразованиеВызовСервера.ИспользуетсяЦенообразование25(ПараметрыОтбора.Дата)` (строка 507): истина — срез `ЦеныНоменклатуры25` по ключу ценообразования, ложь — срез `ЦеныНоменклатуры` по номенклатуре, характеристике и виду цен. Цена пересчитывается в валюту отбора и на коэффициент упаковки.

## 6. Отчёт о розничных продажах неавтоматизированной точки

Отдельного объекта «неавтоматизированная торговая точка» в конфигурации нет. Тип кассы — `Перечисление.ТипыКассККМ` (`osn\Enums\ТипыКассККМ.xml`): `ФискальныйРегистратор`, `АвтономнаяККМ` (синоним «Автономная ККМ»), `ККМOffline`, `АвтономноеРМК`.

Форма `Документ.ОтчетОРозничныхПродажах.Форма.ФормаДокумента`, модуль:

- строка 33: видимость элементов зависит от `РеквизитыКассыККМ.ТипКассы = ФискальныйРегистратор`;
- строки 42–44: для фискального регистратора недоступно копирование;
- строки 305–313: при смене кассы, если вид цен кассы отличается от вида цен документа, вызывается `ЗаполнитьЦеныПоВидуЦен(РеквизитыКассыККМ.ВидЦены)`.

Вид цен кассы — это `КассыККМ.Склад.РозничныйВидЦены`. Функция `Справочники.КассыККМ.РеквизитыКассыККМ` (модуль менеджера, строки 391–398) возвращает его в поле `ВидЦены` и вместе с организацией, складом и валютой переносится в шапку документа.

`ЗаполнитьЦеныПоВидуЦен` (строка 1808) пишет в строки `Товары.Цена` срез `РегистрСведений.ЦеныНоменклатуры` на конец дня даты документа по номенклатуре и характеристике. Запрос идёт в старый регистр, не в `ЦеныНоменклатуры25`. После подстановки цены вызываются `ПересчитатьСумму` и `ПересчитатьСуммуСУчетомРучнойСкидки`.

Для кассы с типом, отличным от фискального регистратора, строки отчёта заполняются на форме, цена подставляется видом цен склада этой кассы. В просмотренном модуле формы отдельного запрета ручного изменения `Товары.Цена` нет. У документа есть реквизит шапки `ВидЦены` (`ОтчетОРозничныхПродажах.xml`, строка 324) и `Товары.ПроцентРучнойСкидки` (строка 1860). ТЧ `СкидкиНаценки` у отчёта нет (список ТЧ: Товары, ВидыЗапасов, Серии, АкцизныеМарки, ОплатаПлатежнымиКартами, ПодарочныеСертификаты, НачислениеБонусныхБаллов, ОплатаБонуснымиБаллами).

## 7. Как узнать нашу скидку в ТЧ и связать со строкой товара

У `Документ.ЗаказКлиента.ТабличнаяЧасть.СкидкиНаценки`:

- `КлючСвязи` — число 10.0, подсказка реквизита: идентификатор связи строки ТЧ «Товары» и строки ТЧ «Скидки (наценки)» (`ЗаказКлиента.xml`, строки 6434–6458);
- `СкидкаНаценка` — `СправочникСсылка.СкидкиНаценки` (строка 6481);
- `Сумма` (строка 6523).

Такой же ключ есть у строки `Товары` (строка 5105). Наша наценка — строки ТЧ, у которых `СкидкаНаценка` равна созданному элементу справочника. Строка товара — `Товары.Найти(КлючСвязи, "КлючСвязи")`.

Те же ТЧ `СкидкиНаценки` есть у `РеализацияТоваровУслуг` и `ЧекККМ`. У `ОтчетОРозничныхПродажах` этой ТЧ нет, связать наценку со строкой по `КлючСвязи` там нельзя.

Ручная скидка строки заказа — `Товары.ПроцентРучнойСкидки` и `Товары.СуммаРучнойСкидки` (строки 4796 и 4843). Это не колонки ТЧ `СкидкиНаценки`.

## 8. Партнёр в сегменте

`РегистрСведений.ПартнерыСегмента`: непериодический, независимый (`ПартнерыСегмента.xml`, строки 159–160). Измерения, ресурсов нет:

- `Сегмент` — `СправочникСсылка.СегментыПартнеров` (строка 179);
- `Партнер` — `СправочникСсылка.Партнеры` (строка 227).

Типовая процедура:

`СегментыСервер.ДобавитьПартнераВСегмент(Сегмент, Партнер) Экспорт` — `osn\CommonModules\СегментыСервер\Ext\Module.bsl`, строки 10–16. Создаёт менеджер записи, заполняет оба измерения и записывает. Отдельного удаления «из всех сегментов, кроме текущего» в этой процедуре нет.
