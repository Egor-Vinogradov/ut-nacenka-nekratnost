# Опись расширений

Два расширения с префиксом `тз_`. Вместе не подключают. Полное `ТестовоеЗадание` 1.1.0.0 — демонстрация со встроенными тестовыми данными. Пользовательское `ТестовоеЗаданиеПользователь` 1.0.1.0 — механизм для клиента. УТ 11.5.27.101, платформа 8.5.1.1343. Поддержка конфигурации не снимается.

## 3. Роли и контекст

`тз_ОбщиеПрава` — чтение четырёх регистров и констант процента и ссылки на скидку. В полной версии ещё чтение `тз_ОтладкаКонтроля`. БСП добавляет роль в профили с `ПолныеПрава`, `БазовыеПраваБСП` или `БазовыеПраваВнешнихПользователейБСП`. Основные роли расширения платформа назначила бы всем, но БСП снимает флажок «использовать основные роли для всех пользователей» и оставляет только роли профилей. Подробности: `tz_etap5.md`, «Права обычного пользователя».

| Объект | Чтение | Запись |
| --- | --- | --- |
| тз_КратностьПродажи | безопасный режим внешней обработки расчёта | команда настройки, обычный сеанс полноправного |
| тз_ПроцентНаценкиЗаНекратность | безопасный режим расчёта | команда настройки |
| тз_СкидкаНаценкаЗаНекратность | обычный сеанс проведения | команда настройки |
| тз_ОтладкаКонтроля | обычный сеанс проведения, только полное | вручную. Команда заполнения не пишет |
| тз_УровниПартнеров | обычный: состояние уровня. Привилегированный: подбор соглашения и контроль цены | привилегированный, команда уровня и запись партнёра или контрагента |
| тз_УровниПокупателейПоИНН | обычный | привилегированный, загрузка CSV и применение по ИНН |
| тз_СоглашенияУровней | привилегированный при подборе и записи сегмента. Роль чтения тоже даёт чтение | привилегированный, команда заполнения полного расширения и ручная настройка |
| ПартнерыСегмента | привилегированный | привилегированный. Роль `тз_ОбщиеПрава` состав сегмента не меняет |

Привилегированный режим включается на время операции и выключается. Из безопасного режима внешней обработки наценки он не вызывается: `Рассчитать` читает только кратность и процент.

## 5. Ограничения

- Вычисляемые виды цен регламент `ОбновлениеЦен` может пересчитать. Команда полной версии не меняет способ задания цены.
- Розничная цена кассы записана в вычисляемый вид напрямую (только полное расширение).
- Отчёт о розничных продажах контролирует цену, не сумму наценки.
- Уже пробитый чек: предупреждение в журнал, отказ не ставится.
- Перестройка групп скидок переносит элементы и меняет вариант корня. Обратной команды нет.
- Партнёр без записи уровня остаётся на типовом подборе.
- Менеджер может выбрать другое доступное соглашение. Цена строки всё равно сравнивается с ценой уровня.
- Безопасный режим расширения должен быть снят, иначе нет привилегированной записи и нет роли обхода у администраторов.
- Создание клиента менеджеру закрывает типовой профиль, не расширение.
- Менеджеру закрыты внешние обработки, справочник скидок, установка цен, типовые соглашения, пользователи и раздел «тз Наценки и уровни».
- Соглашения чужих уровней клиенту недоступны из-за сегментов.
- Пока в строке выбран вид цен уровня, цена в форме не редактируется. Это поведение УТ.
- Отменить автоматическую наценку нельзя: скидка неуправляемая.
- Контроль «соглашение документа совпадает с уровнем» не делается.

## 7. Требование и проверка

| Требование | Как реализовано | Чем проверено |
| --- | --- | --- |
| Наценка, если количество не кратно кратности вида | Внешняя обработка, процент из константы, кратность в регистре | Сценарий полной версии, таблица 5+4+2+отходы. Пользовательский заказ 9 шт, сумма 9180 |
| Наценка увеличивает сумму | В скидках сумма отрицательная | 9 × 850 = 7650, наценка −1530, сумма 9180. Серебро 10044, бронза 10800 |
| Ручная скидка на строке с наценкой запрещена | Контроль при проведении | Отказ на 5% и на ручную наценку −5% под менеджером |
| Цена не ниже вида цен уровня | Цепочка строка → соглашение → уровень | Произвольная 800 отказ, 850 проводится. Серебро 900 отказ, порог 930 |
| Уровни бронза, серебро, золото и подстановка соглашения | Регистры, сегмент из соглашения, `&Вместо` подбора | Три заказа полной версии. Под менеджером соглашение золота подставилось |
| ИНН задаёт уровень, ручной не затирается | Запись контрагента и команда уровня | CSV и смена уровня в сценарии полной версии. Новый клиент под Admin |
| РМК считает ту же наценку и не печатает чек при отказе | Контроль `ПередЗаписью` до фискализации | 9 рулонов к оплате 10800. Некратное без пересчёта печать не начинает |
| Пробитый чек не блокируется задним числом | Журнал, уровень предупреждение, без отказа | Сценарий этапа 3 |
| Наценка действует вместе с другими скидками | Перестройка групп, корень «сложение» | Таблица кондиционера и обоев в сценарии полной версии |
| Клиенту не отдавать тестовые данные | Отдельное расширение и ручная настройка | `TestZadanie_user\README.md`, путь Б |
| Любой пользователь читает регистры расширения | `тз_ОбщиеПрава` в профилях БСП | `scripts\diag_roles.txt`: у «Продажи (ГладилинаВМ)» чтение всех регистров и констант. Заказ 9 шт проведён без ошибки прав |
| Обход контроля только явной ролью | `РольДоступна`, не полноправность | Группа «тз Обход наценки», затем Admin из неё убирают |
