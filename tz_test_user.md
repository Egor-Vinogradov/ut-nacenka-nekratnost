# Проверка пользовательского расширения

База `F:\1с\TestCoder\БазаПользователь`, список «TestCoder Пользователь». Расширение `ТестовоеЗаданиеПользователь`. Полное расширение не подключено. Данные ниже создаются вручную, команда заполнения в этом расширении отсутствует.

## Подготовка

1. Полноправным пользователем выполнить «тз Первоначальная настройка». В протоколе константа скидок включена, процент 20, обработка и скидка «Наценка за некратность упаковке» записаны, действие на пустой склад действует. Регистр соглашений ещё пуст — протокол просит его заполнить.
2. Вид номенклатуры обоев с использованием упаковок. В «тз Кратность продажи» для этого вида указать 4.
3. Одна номенклатура этого вида, цена закупки или ручной ввод не нужны: дальше работают три вида цен.
4. Три вида цен, например бронзовый 1000, серебряный 930, золотой 850. Три типовых соглашения, у каждого свой вид цен и свой сегмент клиентов.
5. «тз Соглашения уровней»: бронзовый, серебряный и золотой — соответствующие соглашение и вид цен.
6. Два клиента. У первого ИНН из регистра со серебряным уровнем либо уровень задан командой «тз Уровень покупателя». У второго — золотой. После записи контрагента партнёр попадает в сегмент соглашения своего уровня.

## Сценарий

1. Заказ клиента серебряного уровня, 3 рулона обоев. Рассчитать скидки. Строка получает наценку 20% от суммы до скидок: база 3 × цена серебряного вида цен, наценка 20%. Провести. Документ проводится.
2. На строку с наценкой поставить ручную скидку и провести. Отказ: ручная скидка на строке с наценкой за некратность не допускается.
3. Убрать ручную скидку, поставить цену строки ниже вида цен серебряного соглашения и провести. Отказ: цена ниже цены по виду цен.
4. Вернуть цену, сменить клиенту уровень на золотой командой «тз Уровень покупателя». Новый заказ подбирает золотое соглашение: вид цен и сегмент другие, наценка снова только если количество не кратно 4.
5. Чек ККМ в РМК на ту же номенклатуру, 3 единицы, «Рассчитать скидки», затем резерв перед оплатой. Сообщения «в документе 0» нет: у записи «К оплате» `СкидкиРассчитаны = Ложь`. После повторного расчёта пробитие сверяет табличную часть скидок.
